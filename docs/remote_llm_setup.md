# Удалённый LLM для разработки: llama-server на Маке

Быстрый путь на время разработки: модель крутится на Маке, iPhone ходит к ней
по Wi-Fi через `RemoteProvider`. Цель — видеть сквозной поток SOS→JSON в
приложении, не дожидаясь интеграции llama.swift на устройстве.

## Что нужно, чтобы работало

### 1. Узнать IP Мака в локальной сети

Открой Терминал на Маке и выполни:

```
ipconfig getifaddr en0
```

Выведется адрес вида `172.20.10.2`. Если пусто — попробуй `en1`
(значит Мак подключён другим интерфейсом).

Сейчас используется схема «телефон раздаёт интернет»: iPhone — точка
доступа (`172.20.10.1`), Мак подключён к ней и получил `172.20.10.2`.
В этой схеме изоляции клиентов нет — телефон видит Мак напрямую.

Сейчас в приложении прописан **`http://172.20.10.2:8080`**
(файл `ios/RM/RM/LLM/LLMModelConfig.swift`, профиль `remoteDev`, поле `host`).
Если IP Мака сменился (другая сеть, роутер перевыдал адрес) — поменяй эту
одну строку и пересобери приложение.

### 2. Запустить llama-server на Маке

```
cd ~/Bonsai-demo && caffeinate -ims ./bin/mac/llama-server \
  -m ~/Bonsai-demo/models/qwen3-4b/Qwen_Qwen3-4B-Instruct-2507-Q4_K_M.gguf \
  --host 0.0.0.0 --port 8080 -ngl 999 -fa on -c 8192 \
  --temp 0.5 --top-p 0.85 --top-k 20 --min-p 0 --jinja
```

Важное:
- `--host 0.0.0.0` — обязателен, иначе сервер слушает только сам Мак
  и телефон его не увидит;
- `caffeinate -ims` — не даёт Маку уснуть, пока сервер работает;
- остановить: Ctrl+C в том окне Терминала
  (или `kill $(lsof -ti TCP:8080)` из другого).

Файрвол Мака: `llama-server` уже добавлен в список разрешённых
(25.07.2026). Если после обновления бинарника телефон перестанет
подключаться — Системные настройки → Сеть → Брандмауэр → разрешить
входящие для llama-server.

### 3. Телефон — в той же Wi-Fi, что и Мак

Проверка без приложения: открой на iPhone Safari и зайди на
`http://172.20.10.2:8080/health` — должно показать `{"status":"ok"}`.
Если не открывается — проблема в сети/файрволе, не в приложении.

При первом запросе из приложения iOS спросит разрешение
**«Локальная сеть»** — обязательно разрешить.

Замечание: с самого Мака `curl http://172.20.10.2:8080/health` может
«висеть» — это защита «Локальная сеть» macOS для процесса терминала,
к доступности сервера с телефона отношения не имеет.

## Как это устроено в приложении

- `RemoteProvider` (`ios/RM/RM/LLM/Providers/RemoteProvider.swift`) —
  третья реализация `LLMProvider`: HTTP к llama-server.
  - свободная генерация → `/v1/chat/completions` (сервер применяет
    chat-шаблон модели);
  - генерация со схемой → `/completion` с `json_schema` — грамматика
    строится и применяется НА СЕРВЕРЕ (тот же путь, что тест №6 бенчмарка);
  - объявляет `structuredOutput` — валидация кодом и repair-попытка
    в `StructuredLLM` при этом остаются (грамматика гарантирует формат,
    но не смысл).
- Активный конфиг — `LLMModelConfig.defaultConfig = remoteDev`
  (провайдер `remote`, host Мака, модель Qwen3-4B на сервере).
- Экран «SOS → JSON» — первая вкладка приложения: текст → «Извлечь SOS» →
  карточка результата + сырой JSON + скорость.

`reports/ondevice_phase2.md`). Remote-путь из этого дока остаётся

`llm_config.json`). Больше ничего менять не нужно — в этом смысл
абстракции `LLMProvider` (см. `llm_architecture.md`).
