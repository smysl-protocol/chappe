# Сглаживание на приёме — дизайн (Б8, 29.07.2026; кода нет)

## Проблема

Машинная развёртка кодов у получателя — пиджин («Мы вернуть вокруг
12»). Прогонять её через модель ПРИЁМНИКА напрямую нельзя: модель
на приёме отменяет детерминизм — два получателя с разными моделями
увидят разный текст одного блоба.

## Решение: сглаживание — слой ОТОБРАЖЕНИЯ, не декодирования

1. **Истина — канонический табличный рендер.** Он детерминирован
   (байты → одна и та же строка на любом устройстве), он хранится в
   записи и **всегда доступен по тапу** («показать дословно»). Все
   гейты, сверки, экспорт, цитирование работают ТОЛЬКО с каноном.
2. **Сглаженный текст** — необязательное украшение поверх: локальная
   модель получателя переписывает канонический рендер по-русски.
   Считается на устройстве, не передаётся, не сохраняется как истина
   (хранится рядом, помечен «сглажено», пересчитывается при смене
   модели).
3. **Гейт фактов обязателен**: каждое ЧИСЛО, ИМЯ (esc_name),
   ОТРИЦАНИЕ (коды/структура) и ВРЕМЯ (esc_time, метка «(к HH:MM)»)
   из канона обязано присутствовать в сглаженном варианте —
   проверка детерминированным кодом (экстрактор фактов, как в ферме).
   Не сошлось → показываем канон, без повторных попыток в UI-потоке.
4. **Честная маркировка**: сглаженный пузырь несёт бейдж «сглажено ·
   дословно по тапу». Получатель всегда знает, что видит пересказ.
5. **Модель вне доверенного пути** (правило №1 проекта): сглаживание
   не влияет ни на байты, ни на ack, ни на статусы, ни на решения.

## Отношение к петле отправителя

Симметрия: у отправителя петля правит ЕГО текст до кодирования (и
сверяется гейтами до эфира); у получателя сглаживание правит только
ЕГО отображение после декодирования. Провод в обоих случаях несёт
одни и те же коды — детерминизм приёма сохраняется по построению.

## Стоимость и когда делать

Один вызов локальной модели на входящее сообщение (~1-3 с на
телефоне, лениво — при показе пузыря, не при приёме). Реализация —
после полевой проверки бэклога v1.2 (не раньше словарной итерации).
