# Слой карты R+M — живой документ

Статус: в работе (ночь 28.07.2026, ветка `feat/map-layer`).
Связанные документы: `docs/adr/003-tile-stack.md` (выбор тайлового стека),
`docs/RM_Envelope_v0.md` §5 (координаты в протоколе), `docs/sophie_presence.md`
§4 (гео-инструменты Каи).

## 1. Тайловый стек и обоснование

Решение фиксируется в `docs/adr/003-tile-stack.md`. Кратко:

- **MapKit исключён** — Apple не даёт легального офлайн-кэша тайлов, а офлайн
  для нас условие задачи, не режим.
- Рендер: **MapLibre Native iOS**, SPM-пакет `maplibre-gl-native-distribution`
  **6.28.0** (правило SPM `6.28.0 ..< 7.0.0`) — утверждено владельцем по итогам
  WP1. Векторные тайлы, стиль на базе OSM, только тёмный вариант.
- Офлайн: **штатные offline packs** (`MLNOfflineStorage` +
  `MLNTilePyramidOfflineRegion`) — произвольный bbox с зумами, пауза и
  возобновление штатные, pack тянет тайлы + стиль + glyphs + sprites разом.
- Тайлы и стиль: **OpenFreeMap** (`tiles.openfreemap.org/styles/dark`) —
  схема OpenMapTiles, без ключа и лимитов; URL в конфиге, self-hosting —
  запасной выход. PMTiles/MBTiles отвергнуты (офлайн-пак с ними не работает /
  нет пути bbox→файл без сервера) — подробности и ссылки в ADR 003.
- Атрибуция на экране карты: «© OpenStreetMap contributors | OpenFreeMap
  © OpenMapTiles» + штатная кнопка атрибуции MLNMapView.

Экран и модель данных не знают, что внутри: доступ к тайлам только через
протокол `MapTileStore` (WP2), смена стека не переписывает экран.

## 2. Модель региональных пакетов

Регион — прямоугольник, скачанный заранее по интернету. По мешу тайлы не
поедут никогда: регион — десятки мегабайт, канал LoRa — сотни байт на пакет.
Это физика, а не настройка.

Модель (`MapRegion`):

| Поле | Что это |
|---|---|
| `id` | стабильный идентификатор региона |
| `name` | человекочитаемое имя («Гибралтарский пролив») |
| `bbox` | границы: minLat/minLon/maxLat/maxLon |
| `zoomRange` | диапазон зумов (по умолчанию 0–14) |
| `sizeBytes` | фактический размер на диске |
| `downloadedAt` | дата скачивания |
| `styleVersion` | версия стиля, под которую качались тайлы |
| `state` | нет / качается (прогресс) / готов / устарел |

`RegionDownloader`: докачка с паузой и возобновлением, поведение при обрыве
сети — пауза без потери прогресса, дисковый бюджет с предупреждением до
начала скачивания, удаление с освобождением места. Скачивание только при
интернете.

`CoverageIndex`: быстрый ответ «есть ли тайлы в этой точке» — по bbox готовых
регионов. Нужен экрану (серые зоны) и инструменту Каи `tile_coverage`.

Сценарий «перед выходом» — первоклассный: выбор области прямоугольником,
**вес показывается до начала скачивания**, список скачанного с размерами.

Как реализовано (ночь 28.07): отдельного `RegionCatalog` нет — метаданные
региона (имя, bbox, зумы, версия стиля) лежат в `context` самого
offline-pack'а, регионы всегда пересобираются из фактических pack'ов и
не могут разъехаться с базой. «Прямоугольник» v1 — видимая область карты
(как в официальном примере MapLibre), рисования рамки нет. Вес до
скачивания — расчётный: число тайлов (слиппи-сетка) × средний вес из
конфига (`map.estimatedTileBytes`, дефолт 45 КБ) — в UI подписан «~».
Файлы: `ios/RM/RM/Tiles/MapTileStore.swift`, `RegionDownloader.swift`,
экран — `ios/RM/RM/Map/RegionManagerScreen.swift`.

## 3. Модель позиции и старения

### Позиция

```swift
struct PositionFix {
    let lat: Double
    let lon: Double
    let horizontalAccuracy: Double   // метры, из CoreLocation
    let timestamp: Date
    let source: PositionSource       // .own, .peer(ContactID), .manual
    let precision: PositionPrecision // .exact, .coarse(geohashLength)
}
```

### Кодек — не новый формат

Точные координаты уже канонизированы в Envelope v0 §5: обе оси квантуются
в u24 умножением на 16777215 с округлением floor(x + 0.5), сериализация
lat LE24 + lon LE24 = **6 байт**, разрешение ~1.2 м по широте и ~2.4 м по
долготе. `PositionCodec` — тонкая обёртка над `Envelope.encodeFineCoords` /
`decodeFineCoords`; второго формата координат в проекте нет. Побайтовые
векторы: `tests/position_codec_vectors.json` (генератор
`sim/position_codec_vectors_gen.py` использует `sim/envelope.py` напрямую).

Транспорт позиции — существующий класс `LOCATION` (0x5): личный, сквозное
шифрование, без фрагментации. Новых классов пакетов слой карты не вводит.

### Старение — центральное свойство

Точка без времени врёт. Радиус неопределённости детерминирован:

```
r(t) = horizontalAccuracy + 1.4 м/с × Δt,  сверху 5 км
```

Пороги отображения: <5 мин — плотная точка; <1 ч — точка с растущим кругом;
<6 ч — приглушённая; старше — архивный вид / скрытие по настройке.
Подпись возраста («40 минут назад») обязательна на каждой метке, не в попапе.

### Источник позиций собеседников

В брифе сказано «последняя известная позиция уже летает в защищённом слое».
Фактически в коде (на начало ночи): `LocationMessage` определён и покрыт
тестами, но **не отправляется, не принимается и не хранится**; в словаре есть
код `loc_last_known` (0x0059) и escape `esc_coords` (0xF001), но `esc_coords`
не реализован ни в одном кодеке. Расхождение зафиксировано в отчёте.
Слой карты заводит `PeerPositionStore` — единственное хранилище принятых
позиций (по одной, последней, на контакт); источник — входящие `LOCATION`-
пакеты. Второго источника правды нет.

### LocationProvider

Никакого непрерывного GPS. Обновление по событиям: отправка сообщения,
явный запрос пользователя, выдача гранта. Разрешение — **только
When-In-Use**; Always, significant-change, region monitoring и visits не
используются и не запрашиваются (решение разработчика, 29.07).

**Фон на время гранта (решение 29.07, проверено по актуальной доке
Apple, не по памяти):** механизм — **`CLBackgroundActivitySession`**
(iOS 17+; наш target 26.5). По статье «Handling location updates in the
background»: это современный путь для When-In-Use-приложений получать
обновления в фоне (с видимым индикатором), рекомендованный вместо
legacy `allowsBackgroundLocationUpdates`; ключ `UIBackgroundModes =
location` в Info.plist обязателен для обоих путей (добавлен). Ловушка с
`NSInternalInconsistencyException` относится к legacy-пути без ключа —
мы на него не наступаем, т.к. ключ есть, а legacy-флаг не трогаем.

Жизненный цикл сессии = жизненный цикл гранта (`ShareSessionController`):
создаётся при выдаче гранта; гасится при отзыве и истечении (таймер на
ближайший expiresAt). Сессия умирает с процессом, но (решение 29.07,
закрытие сессии): **если грант ещё жив по таймеру и пользователь открыл
приложение вручную — сессия возобновляется автоматически** (открытие =
действие человека; система сама приложение не поднимает), с явным
состоянием «грант активен, обновления возобновлены» в меню гранта.
Вне активного гранта фоновые обновления не включаются никогда;
переходное состояние «грант активен, обновления не идут» тоже
представимо и показывается явно.

## 4. Политика раскрытия координат

Принцип тот же, что у шёпота Каи: **гарантия кода, а не интерфейса**.
Координата не может попасть в исходящую очередь envelope иначе как через
`LocationDisclosurePolicy` — единственную дверь.

- Шеринг **выключен по умолчанию**.
- Грант адресный: контакт + TTL + уровень точности, с автоистечением и
  видимым индикатором, пока активен.
- Точность — часть гранта: `.exact` либо `.coarse(n)` через усечение геохеша
  (6 симв. ≈ 1.2 км, 5 ≈ 4.9 км, 4 ≈ 39 км). Загрубление — **при
  кодировании**: в эфир уходит центр ячейки геохеша, закодированный тем же
  6-байтовым кодеком; восстановить точность из байтов невозможно.
- Отзыв мгновенный и односторонний: следующий маячок не уходит.

Единственная легальная цепочка: `LocationProvider` → `LocationDisclosurePolicy
.disclose` (проверка гранта + загрубление) → `DisclosedPosition` (создать может
только политика — fileprivate init) → `Outbox.enqueueLocation` (принимает
ТОЛЬКО DisclosedPosition) → очередь. Аудит 28.07: других путей координаты в
реальную очередь нет; SOS-демо гоняет пакеты через in-memory симулятор LoRa
с координатами-заглушкой (Бали) и в Outbox не пишет. Полный перечень — в
REPORT_map_night.md.

Существующие исключения вне слоя карты (были до него, картой не трогаются):
SOS и BEACON несут грубые координаты (~300×600 м) по явному действию
пользователя — это зафиксировано в Envelope v0 §3 и CLAUDE.md.

## 5. Контракты гео-инструментов Каи

Регистрация — в существующем реестре (`SophieTools.swift`: case в enum +
значение в схеме + описание в промпте + ветка исполнения). Приоритет —
существующий P2 (интерактив), новых уровней нет. Числа считает код, модель
только формулирует. Возраст данных — обязательное поле каждого результата:
ответ «он в 3 км» без «по данным 40-минутной давности» недопустим по схеме.

| Инструмент | Вход | Выход (всё считает код) |
|---|---|---|
| `own_position` | — | lat, lon, accuracy_m, age_s |
| `peer_position` | contact_id | lat, lon, accuracy_m, **age_s обязателен** |
| `distance_bearing` | from, to | distance_m, bearing_deg (гаверсинус R=6371000) |
| `walk_eta` | distance_m | eta_s = distance / 1.4 м/с + пометка «по прямой, не маршрут» |
| `tile_coverage` | lat, lon | covered: bool, region_name? |

Правило радио-тишины (sophie_presence §4): инструменты не создают эфир;
нет позиции — Кая честно говорит и может предложить запросить, отправка
только явным действием человека.

## 6. Бюджет батареи и эфира

- **Эфир:** позиционные маячки — второй по объёму источник трафика после
  сообщений. Лимит: не более N маячков в час на контакт; N в конфиге
  (`map.maxBeaconsPerHour`), **дефолт 6** — раз в 10 минут: за это время
  пешеход уходит ≤ 840 м, что честно показывает круг старения, а нагрузка
  на эфир остаётся ~2% дьюти-цикла в худшем случае. При утилизации канала
  выше порога (`map.beaconSuppressUtil`, дефолт 0.5) маячки подавляются
  целиком. Событие для маячка — отправка сообщения контакту (плюс момент
  выдачи гранта); таймеров нет. Реализация: `BeaconBudget` (чистая
  арифметика окна) + `PositionBeacon.afterMessageSent` →
  `LocationDisclosurePolicy.disclose` → `Outbox.enqueueLocation`.
  Источника реальной утилизации канала до Meshtastic BLE нет — сейчас 0.
- **Батарея:** GPS только по событиям; непрерывной подписки нет. Замеры —
  в отчёте (что не измерено — честно помечено).
- **Диск:** предупреждение при скачивании региона, если свободного места
  меньше порога.

## 7. Открытые вопросы

1. **Пограничный случай формата:** lat=+90.0 и lon=+180.0 кодируются как
   0xFFFFFF — байт-в-байт совпадает с сентинелом «координат нет»
   (`Envelope.noFine`). На практике недостижимо (нужен фикс ровно на полюсе/
   антимеридиане), но в спеке Envelope v0 стоит отметить. Решение за
   владельцем — слой карты формат не трогает.
2. ~~Фоновая отправка маячков~~ — **решено 29.07**: When-In-Use +
   `CLBackgroundActivitySession` строго на время гранта, ключ
   `UIBackgroundModes = location` добавлен; см. §3.
3. `esc_coords` (0xF001) в семантическом кодеке не реализован — позиция
   в потоке кодов передаваться не может, только полями envelope. Слою карты
   хватает `LOCATION`; реализация esc_coords — вне ночной задачи (словарь
   заморожен, П.1 правил).
4. Версионирование стиля против скачанных тайлов: при смене styleVersion
   помечать регионы «устарел» или перекачивать молча? Пока — помечаем.
5. Протокол запроса позиции («попроси его поделиться») — пакета-запроса нет;
   v1: просьба уходит обычным текстом, автоматики нет.
