## 0. Зачем и что разблокирует

Сейчас рабочий путь — RemoteProvider через llama-server на Маке. Локальный
провайдер на iPhone разблокирует: гейт приватности шёпота Каи
(provider.kind == .local), честное «на устройстве», замер реальной скорости
конвейера на телефонном железе.

## 1. Решения по развилкам

**Биндинг: XCFramework, пин на релизный тег b10107** (решение изменено
26.07.2026 после сверки с README). Причина: SPM-путь в апстриме больше
не существует — Package.swift удалён из ggml-org/llama.cpp (проверено:
404 на master), README примера examples/llama.swiftui рекомендует именно
XCFramework («run ./build-xcframework.sh… adding build-apple/llama.xcframework»).
**Канонический дом моделей — `~/RM/models/`**, llama-server запускать
с моделью оттуда же (правило от 26.07.2026: 4B жил только в
`~/Bonsai-demo/models/`, из-за чего devicectl-копирование падало с
CoreDeviceError 7000 — источник не существовал по ожидаемому пути).

Берём не самосборку, а **готовый артефакт релиза**
`llama-b10107-xcframework.zip` (тот же билд оборачивает mattt/llama.swift
версией 2.10107.0). Подключение: xcframework лежит в локальном SPM-пакете
`ios/LlamaKit` (binaryTarget; сам бинарь в git не кладём — качается
скриптом `scripts/fetch_llama_xcframework.sh`). Сторонние обёртки не
используем: у нас свой протокол LLMProvider, нужен тонкий LlamaCppProvider
под него.

**Модель:** Qwen3-4B-Instruct-2507 Q4_K_M (~2.5 ГБ) — тот же GGUF, что уже
работает на Маке. Доставка по фазам: dev — перенос файла на iPhone через
Finder/AirDrop + импорт в приложение (Files); прод-загрузчик (пиненный URL,
SHA256, докачка в фоне) — фаза 3, сейчас не делаем. С первого дня: файл
хранится в Application Support с isExcludedFromBackup = true (не заливать
2.5 ГБ в iCloud-бэкап людям).

**Параметры старта:** контекст 4096, Metal on, mmap on, temperature 0
(грид) для воспроизводимости против эталона. KV-сессии — фаза 2
(sophie_presence §5, capability).

## 2. Фазы

**Фаза 1 — каркас (без большой модели).**
SPM-зависимость; LlamaCppProvider: load(modelPath)/generate(prompt,
schema?)/cancel, конформный LLMProvider; выбор провайдера в dev-меню;
смоук на КРОШЕЧНОЙ модели (Qwen2.5-0.5B-Instruct Q4 или аналог, ~400 МБ) —
проверяем сборку, Metal, токены текут, cancel работает. Критерий: приложение
на реальном iPhone генерирует связный ответ локально; симулятор не считается
(Metal там не работает — только CPU, не показатель).

**Фаза 2 — боевая модель + эталонная сверка.**
Импорт 4B GGUF через Files/AirDrop; прогон 12 диктовок
(dictation_corpus.jsonl) через локальный провайдер тем же промптом, что в
pipeline.py; сравнение пивотов с прогоном llama-server (та же модель,
temperature 0 → расхождения только от билда). Замеры: время загрузки модели,
prefill ток/с, decode ток/с, пиковая RAM, деградация при троттлинге
(5 мин непрерывной работы). Критерий: SOS-извлечение и пивот работают
на устройстве; факты ≥ уровня удалённого прогона (35/44); цифры скорости
записаны в docs/reports/.

**Фаза 3 — прод-доставка модели** (позже, отдельным заходом): загрузчик,
SHA256, докачка, проверка свободного места (~3.5 ГБ), UX первого запуска.

## 2а. Фаза 1 — как проверить на телефоне (владельцу)

1. **Один раз после клона репозитория:** в Терминале выполнить
   `~/RM/scripts/fetch_llama_xcframework.sh` — скачает llama.xcframework
   (b10107) в `ios/LlamaKit/`. Без этого проект не соберётся: первая
   фаза сборки таргета RM проверяет наличие фреймворка и падает с
   понятным сообщением «run scripts/fetch_llama_xcframework.sh»
   (а не с невнятным «Missing package product 'llama'», как было).
   Если Xcode уже показал Missing package product — после скачивания
   сделай File → Packages → Reset Package Caches.
2. Смоук-модель уже лежит на Маке: `~/RM/models/Qwen2.5-0.5B-Instruct-Q4_K_M.gguf`
   (~400 МБ).
3. **Перенести файл на iPhone:** подключи iPhone кабелем → Finder →
   выбери iPhone в боковой панели → вкладка «Файлы» → перетащи GGUF-файл
   на приложение **RM** в списке. (Альтернатива: AirDrop → «Сохранить
   в Файлы» → папка On My iPhone.)
4. В приложении: вкладка **Dev** → «Импортировать GGUF…» → выбери файл
   (для Finder-переноса он в On My iPhone → RM; для AirDrop — там, куда
   сохранил). Файл скопируется в хранилище приложения (Application
   Support, из iCloud-бэкапа исключён).
5. Тапни модель в списке (появится галочка) → «Сгенерировать (temp 0)».
   Критерий фазы: связный русский ответ, скорость показана, «Отмена»
   посреди генерации срабатывает (статус «Отменено»).
6. Вернуться на сетевой путь: кнопка «Переключить на remote (Мак)».

## 3. Риски

- **Память/jetsam — риск смягчён данными фазы 2** (26.07.2026,
  reports/ondevice_phase2.md): пик phys_footprint всего **702 МБ** при
  модели 2.33 ГБ — mmap-веса file-backed и в jetsam-метрику почти не
  входят. Требование «только 8 ГБ RAM» под вопросом: вероятно, хватит
  и 6 ГБ — проверить на 6-гигабайтном устройстве при случае. Оговорка:
  под давлением памяти вытеснение mmap-страниц замедлит декод
  (перечитывание с диска) — деградация скоростью, не смертью процесса.
- **Троттлинг:** замер фазы 2 обязателен; длинные фоновые суммаризации (P3)
  проектировались прерываемыми в том числе поэтому.
- **Симулятор бесполезен** для оценки скорости — только реальное устройство.
- **Версионный дрейф llama.cpp:** пин на тег; обновление тега — осознанный
  коммит с перегоном фазы-2 сверки.
