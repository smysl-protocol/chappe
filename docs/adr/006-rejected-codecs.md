# ADR 006 — Отклонённые альтернативы словарного кодека

Дата: 02.08.2026. Статус: принято (фиксация отказов).
Решение: остаёмся на словарном кодеке (Smysl v1.1.0, канонический
Хаффман); альтернативы ниже отклонены. Ветки и артефакты экспериментов
сохранены — не удалять.

## 1. Smysl_v3 — нейрокодек поверх Qwen: ОТКЛОНЁН

Идея: сжатие смысла весами локальной модели (Qwen3-4B) вместо явного
словаря; декодирование — той же моделью на приёме.

Измеренные показатели (цифры приложит владелец по итогам своих
прогонов — места размечены, значения не выдуманы):

| Метрика | Словарный v2 | Smysl_v3 | Комментарий |
|---|---|---|---|
| Средний размер сообщения, Б | ⟨заполнит владелец⟩ | ⟨заполнит владелец⟩ | |
| Доля расхождений декода между устройствами | — | ⟨заполнит владелец⟩ | ключевой провал |
| Время кодирования на сообщение | ⟨заполнит владелец⟩ | ⟨заполнит владелец⟩ | |
| Энергия на сообщение | ⟨заполнит владелец⟩ | ⟨заполнит владелец⟩ | |

Причины отказа (качественные, подтверждены экспериментом):
- декод зависит от весов модели: одно и то же сообщение на разных
  устройствах/версиях модели восстанавливается по-разному;
- энергетическая цена вызова 4B-модели на каждое сообщение
  несовместима с полевым сценарием;
- недетерминизм несовместим с каноничностью (непреложное правило П7).

## 2. ts_sms — статистическое сжатие коротких сообщений: ОТКЛОНЁН

Изучен как готовая альтернатива. Причины отказа:
- вычислительно тяжёл и дорог для мессенджера на телефоне;
- поведение непредсказуемо между устройствами — тот же корень, что у
  нейрокодека: результат зависит от локального состояния, а не только
  от байтов на проводе.

## Общий вывод

**Любой кодек, зависящий от вывода модели, привязывает совместимость
сообщений к версии модели.** У людей разные телефоны и разные
обновления — протокол должен быть один. Формат провода обязан
определяться только версионированными таблицами, которые можно
проверить отпечатком, и ничем больше.

## Условия переоткрытия идеи

Возвращаться к модельным кодекам имеет смысл только если одновременно:
1. появится способ **побитово детерминированного** вывода одной и той
   же малой модели на всех целевых устройствах (фиксированные веса с
   отпечатком в протоколе, целочисленный инференс, без плавающей
   лотереи Metal/ANE/CPU);
2. модель-кодек будет отдельным маленьким артефактом с собственной
   версией в конверте (как таблица Хаффмана), а не «той LLM, что стоит
   у пользователя»;
3. энергетика: кодирование сообщения дешевле передачи сэкономленных
   байт по радио (сейчас наоборот на порядки);
4. останется литерал-фоллбэк, не зависящий от модели, — на случай
   расхождения версий.

До выполнения всех четырёх пунктов — словарный кодек.

## Дополнение 02.08.2026: замер против обычного сжатия (WP3 крипто-сессии)

Полевой корпус (15 уникальных карточек) + контрольное «про отель»,
уровень сравнения — смысловые байты payload (криптообвязка у всех
методов одинаковая). zstd — уровень 19; словарь zstd обучен
leave-one-out на остальных текстах корпуса (корпус мал — это потолок
честности); Unishox2 — родной компрессор коротких юникод-строк.

| Метод | Среднее, Б (все 16) | Среднее, Б (15 семантических) |
|---|---|---|
| Сырой UTF-8 | 225 | 228 |
| zlib −9 (наш fallback) | 143 | 144 |
| zstd −19 | 148 | 149 |
| zstd −19 + словарь | 99 | 99 |
| Unishox2 | 120 | 121 |
| **Наш кодек** (semantic, fallback→zlib) | **46** | **41** |

Семантический кодек в **2,4 раза** плотнее лучшего универсального
конкурента (zstd со словарём) и в **3,5 раза** плотнее zlib. Отель:
utf-8 203 → zlib 139 → zstd+словарь 97 → Unishox2 113 → наш 35.
Причина ожидаема: универсальные компрессоры платят за возможность
выразить любые байты, наш словарь — только смысл из фиксированного
лексикона, а хвосты добирает литерал-Хаффман.

Примечания к честности замера:
- fallback-текст (1/16) в строке «наш» посчитан по zlib — как в
  продукте;
- отель в одном прогоне фермы разово ушёл в fallback; перепроверка
  3/3 дала стабильные 34 Б блоба — разовый транзиент llama-server,
  не свойство кодека (замечание в отчёт сессии);
- zstd-словарь на большом реальном трафике может подрасти, но и наш
  кодек с живым DictationCorpus будет мериться заново.

На решения этой сессии замер не влияет; зафиксирован как основание
«словарный кодек обгоняет обычное сжатие на нашем трафике кратно».
