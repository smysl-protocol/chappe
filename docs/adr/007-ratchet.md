# ADR 007. Рэтчет: снять 44–76 Б криптообвязки с каждого сообщения

Статус: **ПРИНЯТ вариант Б** (решение владельца 02.08.2026).
Решения владельца той же датой:
- **В отклонён — поглощается Б** (внутри сессии отправитель следует из
  тега эпохи, 0 Б вместо 4 Б отпечатка; незнакомцу отпечаток не работал
  и в В; редкое рукопожатие не окупает вторую ветку формата);
- **личность — из отдельного сида**, НЕ из сида EVM-кошелька
  (два независимых бэкапа: компрометация одного не тянет второй);
- конверт проектируется **один раз**: рэтчет + адресация релейного
  транспорта в одной ревизии — черновик `docs/RM_Envelope_v2_draft.md`.
Реализация — отдельной сессией по этому черновику.

Дата: 02.08.2026. Основание: docs/reports/wire_breakdown.md — на
контрольном сообщении обвязка 102 Б против 35 Б смысла; на «ок» —
96 % провода. Открытый вопрос №1 relay_spec_v0.md.

## Что сегодня

Каждое сообщение — независимый sealed box: свежий эфемерный X25519
(32 Б), случайный nonce (12 Б), тег (16 Б), плюс полный pubkey
отправителя (32 Б) внутри шифртекста. Никакого состояния между
сообщениями. Свойства: сообщения несвязываемы наблюдателем;
компрометация ключа ПОЛУЧАТЕЛЯ вскрывает весь записанный архив
(форвард-секретности по получателю нет — долг 1).

Рэтчет = общее состояние пары «цепочка ключей», из которого выводятся
ключ и nonce каждого сообщения. Тогда eph pubkey (32) и nonce (12) с
провода исчезают, а отправитель определяется сессией (ещё −32 внутри
шифртекста).

## Наши условия против допущений Double Ratchet

Signal-рэтчет спроектирован под онлайн-сервер с очередями. У нас:

| Условие | Что ломается | Решения | Чем платим |
|---|---|---|---|
| Доставка вне порядка, задержка до 48 ч (релей) | Ключ сообщения n нужен раньше n−1 | Стандартно: симметричная цепочка выводится вперёд, пропущенные ключи сохраняются (skipped keys) до прихода отставших | Хранилище пропущенных ключей, потолок MAX_SKIP |
| Потеря без уведомления | Дыра в счётчиках неотличима от «ещё едет» | Пропущенные ключи живут до TTL (предлагаю 14 дней), потом чистка | Сообщение старше TTL нерасшифруемо → явный отказ в UI |
| Узел офлайн неделями | В Signal DH-шаг «протухает»; у симметричной цепочки времени нет вообще | Симметричная цепочка догоняется на любую глубину; DH-ре-ключ — по счётчику, не по времени | Форвард-секретность грубеет: окно уязвимости = вся эпоха |
| Ветвление радио+релей: дубль или ничего | Дубль по уже съеденному ключу; «ничего» — дыра | Дедуп ДО расшифровки по (сессия, счётчик); окно виденных счётчиков | Битовая карта окна (128 бит на диалог) |
| Рассылка нескольким получателям | Общей цепочки на группу нет | N независимых парных сессий (sender keys — вне MVP: групповых чатов нет) | Провод ×N получателей; SOS как был — открытый бродкаст |

**Глубина беспорядка.** Предел — MAX_SKIP = 128 пропущенных ключей на
цепочку (128 × 40 Б ≈ 5 КБ на диалог в худшем случае). Сообщение,
пришедшее с дырой глубже 128 или после чистки TTL, нерасшифруемо.
Пользователь видит: «сообщение не удалось расшифровать — сеанс
обновлён, попросите собеседника отправить ещё раз»; приложение
автоматически шлёт запрос нового рукопожатия (1 пакет, работает по
радио, онлайна не требует). Учитывая релейный потолок 48 ч, реальный
беспорядок — единицы сообщений; 128 — запас на порядок.

## Полная потеря состояния (переустановка, новое устройство)

- **Личность** восстанавливается из бэкапа сид-фразы — офлайн, с
  бумаги. Решено 02.08.2026: сид личности **отдельный**, не
  кошельковый — компрометация бэкапа переписки не отдаёт деньги,
  и наоборот. Цена: две бумаги в бэкапе.
- **Сессии не восстановимы принципиально** (в этом смысл форвард-
  секретности). Лечение автоматическое и офлайновое: входящее по
  мёртвой сессии → отказ расшифровки → ответный запрос рукопожатия →
  собеседник заново шлёт полным sealed-форматом. Ничего, кроме радио,
  не нужно.
- **Цена честно:** 48-часовой релейный архив, запечатанный в мёртвую
  сессию, утрачен навсегда. Митигация — правило самолечения: после
  молчания дольше N дней первое сообщение шлётся полным sealed-форматом
  (это же закрывает «эпоха протухла»).

## Метаданные: что релей видит при рэтчете

Конверт (8 Б) релей видит как сегодня. Новый риск — идентификатор
сессии: постоянный тег связывает все сообщения диалога, чего сегодня
НЕТ (эфемерный ключ каждый раз новый). Митигация — вращающийся тег:
`tag = HMAC(chain_key, counter)[0..4]`, наблюдателю выглядит случайным,
получатель сопоставляет перебором своих сессий × окно счётчиков
(дёшево: контактов единицы). Замечание: релейный ящик и так адресуется
получателем — для релея связываемость по получателю уже существует;
вращающийся тег закрывает радио-наблюдателя. Открытая метка времени
остаётся отдельным вопросом (№5 relay_spec), рэтчет её не трогает.

## Варианты

### Вариант А — полный Double Ratchet (как Signal)

DH-ключ в заголовке КАЖДОГО сообщения (иначе потеря DH-шага рвёт
цепь), счётчики N/PN. На провод: 32 (DH pub) + 4 (счётчики) + 16 (тег)
+ 2 (тег сессии) ≈ 54 Б обвязки вместо 93.

- Плюс: лучшие свойства — форвард-секретность на каждое сообщение,
  самолечение после компрометации (PCS), максимум готового анализа.
- Минус: **32 Б DH-ключа возвращаются в каждое сообщение** — съедена
  главная экономия; сложность состояния максимальная.
- Экономия: ~39 Б/сообщение («ок» 106 → 67 Б).

### Вариант Б — симметричная цепочка с явными ре-ключами (эпохи)

Рукопожатие = сегодняшний sealed (полный формат). Дальше сообщения:
`[кодек 1][тег сессии 4][счётчик 2][шифртекст][тег 16]` = **23 Б**
обвязки. Ключ и nonce — из цепочки KDF; DH-ре-ключ отдельным
сообщением каждые K=100 сообщений или при самолечении после молчания.

- Плюс: максимум экономии — 70 Б/сообщение внутри эпохи; переживает
  любой офлайн; беспорядок — стандартными skipped keys.
- Минус: форвард-секретность с зерном «эпоха», не «сообщение»
  (компрометация состояния вскрывает хвост эпохи до следующего
  ре-ключа); PCS только на ре-ключе.
- Экономия: см. таблицу сценариев.

### Вариант В — без рэтчета: короткий отпечаток отправителя

Минимальный шаг: внутри шифртекста вместо pubkey 32 Б — отпечаток
4 Б (BLAKE/SHA от ключа), полный ключ — только незнакомцам.
Состояния нет, свойства криптографии не меняются вовсе.

- Плюс: тривиален, совместим (новый внутренний маркер), нулевой риск.
- Минус: экономит только 28 Б; eph 32 + nonce 12 остаются.
- Экономия: 28 Б/сообщение («ок» 106 → 78 Б, отель 137 → 109 Б).

## Экономия по сценариям (средний провод на сообщение)

Рукопожатие/ре-ключ амортизируются на серию между ре-ключами.

| Сценарий | Сегодня «ок»/отель | А (Signal) | Б (эпохи) | В (отпечаток) |
|---|---|---|---|---|
| Активная переписка (серия ~50 до ре-ключа) | 106 / 137 | 68 / 99 | **38 / 69** | 78 / 109 |
| Редкая переписка (серия ~5, самолечение после молчания) | 106 / 137 | 71 / 102 | **50 / 81** | 78 / 109 |
| Одиночное незнакомому узлу | 106 / 137 | 106 / 137 | **106 / 137 — экономии нет** | 106 / 137 (ключ обязан быть полным) |

Одиночное сообщение незнакомцу всегда идёт полным sealed-форматом —
рэтчету нечего амортизировать, это честный ноль по всем вариантам.

## Рекомендация (помечено как рекомендация, не решение)

**Б**, с вращающимся тегом сессии и правилом самолечения; **В** можно
взять как быстрый промежуточный шаг (28 Б без риска), он не мешает Б.
А отклонить: DH-ключ в каждом заголовке возвращает главную статью
расхода. Решение и параметры (K, MAX_SKIP, TTL, вывод X25519 из сида
кошелька) — за владельцем; реализация — отдельной сессией после
решения. Любой вариант — смена формата провода → согласовать с
заморозкой словаря (FREEZE.md) и версией конверта.
