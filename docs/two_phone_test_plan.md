# План прогона на двух телефонах (WP3, 05.08.2026)

Подготовка сделана этой сессией: сборка на устройство проверена
(`xcodebuild generic/platform=iOS` — BUILD SUCCEEDED, ночная ревизия
с WP1-политикой пивота и верификацией ключей), сценарии ниже. Сам
прогон — с владельцем, за ОДИН заход: сценарии упорядочены так, что
каждый следующий использует состояние предыдущего, сбрасывать ничего
не нужно.

## Подготовка (один раз, ~10 минут)

1. Оба телефона подключить по очереди, на каждый:
   `tools/dev/run_on_device.sh` (сам найдёт, соберёт, поставит;
   UDID второго навязать `DEVICE_UDID=<udid>`, список —
   `xcrun devicectl list devices`).
2. Релей: локальный на Маке —
   `cd ~/rm-relay && go build -o /tmp/relayd ./cmd/relayd && /tmp/relayd -db /tmp/relay.db -addr 0.0.0.0:8443`;
   на обоих телефонах Dev → «Адрес релея» → `http://<IP Мака>:8443`
   (IP: `ipconfig getifaddr en0`). Телефоны и Мак — в одном Wi-Fi.
3. Наблюдение: два окна терминала с консолями
   (`run_on_device.sh` печатает; смотреть строки `[дневник]`);
   третье окно — ящики релея:
   `python3 tools/dev/relay_client.py watch <url> 5`.
4. Второй телефон — свежая установка (или Dev → сброс личности,
   если появился) — он «новичок» для сценариев 1 и 4.
5. Радио НЕ трогаем до сценария 5: transport = demo — заодно живьём
   виден WP1 (пивот не бежит на чисто-релейном пути).

## Сценарии

### 1. Первый контакт: карточки + probe

| | |
|---|---|
| Руками | А: «+» → «Показать мой код». Б: «+» → «Сканировать код» → подтвердить. Потом наоборот. Б посылает А первое сообщение (5+ слов) |
| Инструмент | консоль А: `[relay] принято из ящика`; консоль Б: `[relay] положено в ящик`; watch: в ящике А появились кадры |
| Успех | контакты появились с бейджем «не сверен» (не «проверен»!); сообщение дошло, пузырь один; probe-кадр виден в ящике (v2-поток без текста) |
| WP1 живьём | до отправки: бейдж одобрения мгновенный, «через интернет — текстом, без задержки» — секунды ожидания НЕТ |

### 2. Переход v1→v2 и session-кодек: 44 и 75 байт живьём

| | |
|---|---|
| Руками | А→Б: «ok» (после того как Б уже ответил хоть раз — сессия подтверждена ответом). Затем А→Б сообщение подлиннее |
| Инструмент | watch ящика Б: размер кадра. Лабораторные ожидания: «ок» — кадр **44 Б**, отель-фраза — **75 Б**; до подтверждения сессии шли v2-sealed **143–172 Б** |
| Успех | размер кадра в ящике упал со ~164 до 44/75 — session-кодек впервые доказан на двух рэтчет-сторонах. Если НЕ упал — фиксируем размеры и НЕ чиним на месте (форензика: `devicectl` копия Ratchet-каталога) |

### 3. QR-сверка: совпадение и подмена

| | |
|---|---|
| Руками | (а) На обоих: чат → печать в шапке → «Сканировать код собеседника», навести на экран напарника. (б) Затем НАРОЧНО: А сканирует код сверки с ТРЕТЬЕГО экрана (мой QR любого другого профиля/старый скрин) |
| Инструмент | глаза: бейджи в списке чатов |
| Успех | (а) оба контакта стали «проверен», печать в шапке — зелёная; (б) громкое «КЛЮЧ НЕ СОВПАЛ», отметка НЕ поставилась |

### 4. Смена ключа: переустановка Б

| | |
|---|---|
| Руками | Б: удалить приложение, поставить заново (`run_on_device.sh`) — новая личность. Б показывает НОВУЮ карточку, А сканирует |
| Инструмент | глаза + консоль А |
| Успех | А НЕ принимает молча: экран «Ключ контакта изменился» (был/стал), «Не принимать» — первым. После явного принятия: контакт один, «непроверен», история чата с Б на месте (переехала к новому id) |

### 5. Оба пути и дедуп msgID

| | |
|---|---|
| Руками | Подключить узел к А (Dev → transport mesh), узел Б — второму. А→Б сообщение при живом релее И живом радио |
| Инструмент | консоль Б: строка `[дедуп] msgID N погашен` — второй путь пришёл и был погашен; в ленте Б — |
| Успех | ОДИН пузырь; в дневнике дедуп-строка. Тот же msgID в watch (кадр релея) и в консоли радио |
| Примечание | с mesh-транспортом пивот снова бежит (радио сконфигурировано — политика WP1); задержка вернётся, это ПРАВИЛЬНО |

### 6. Экраны шеринга позиции (WP4 от 05.08) — глазами

| | |
|---|---|
| Руками | в чате: меню позиции → дать грант с TTL; выключить; попробовать отправить позицию без гранта |
| Инструмент | глаза владельца (первое впечатление!), консоль — маячок после «сообщение ушло» |
| Успех | владелец говорит «понятно/непонятно» по каждому экрану; без гранта позиция НЕ уходит; индикатор виден, пока грант жив |

### 7. Полевая диктовка с паузой (чанки → сегменты → спасение)

| | |
|---|---|
| Руками | СНАЧАЛА подключить узел (иначе WP1 пропустит пивот!). Диктовать с паузой: «встречаемся у моста в семь [пауза 2 с] возьми фонарь и верёвку», в середине второй части ввернуть выдумку-провокацию не выйдет — просто смотреть исход |
| Инструмент | консоль: стадии `[конвейер]`/гейтов; бейдж одобрения |
| Успех | пивот отработал на реальном микрофоне; если гейт завернул одно предложение — в поле смешанный текст (вербатим + коды), а не всё текстом; паузы дали сегменты (лог сегментатора) |

## Что везём домой

- размеры кадров по сценарию 2 (главная цифра сессии);
- вердикты владельца по экранам (сценарий 6);
- любые расхождения — в красные фикстуры ДО починки (правило 4).
