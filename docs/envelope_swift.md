Дата: 25.07.2026. Порт Python-реализации (`sim/`) в iOS-приложение.
Спека — `docs/RM_Envelope_v0.md`, она же источник истины для обеих версий.

## Совместимость с Python — главный критерий

Обе реализации проходят **одни и те же** файлы:

- `tests/envelope_test_vectors.json` — все пакеты **побайтово**
  (Python: `sim/test_envelope.py`, 36 тестов; Swift: `EnvelopeTests`, 23 теста —
  оба зелёные 25.07.2026);
- `tests/needs_mapping.json` — таблица «enum-строка модели ↔ бит маски»,
  единственный источник соответствия; обе стороны сверяются с ним тестами.

Тесты Swift читают файлы репозитория напрямую через `#filePath` — при
переносе каталога тестов пути поправить в `repoFile()`.

Нюанс zlib: сжатые байты Python и Swift могут отличаться (разные реализации
deflate) — это допустимо, обе стороны разворачивают любой корректный поток.
Тест-векторы используют кодек 0 (без сжатия). Каноничность подписи —
внутри одной платформы.

## Debug-цепочка на экране SOS

Вкладка SOS после извлечения показывает полную цепочку
**текст → JSON → байты → эфир → байты → структура → текст**:

1. `NeedsMapping.makeSOSMessage` собирает пакет из результата модели
   (координаты — GPS-заглушка Бали 8.71/115.17, как в тест-векторах);
2. секция «Пакет (envelope)»: размер в байтах и hex;
3. секция «Эфир»: 3 копии через `LoRaChannel` (потери 30%, дубли 10%,
   перестановка 20%, seed = msg_id — прогон воспроизводим), сколько дошло
   и сколько байт ушло в эфир;
4. секция «Принято и развёрнуто»: принимающая сторона (эмуляция в том же
   приложении) разворачивает первый дошедший пакет в человекочитаемый вид.
   Если не дошла ни одна копия — честно показывается «все потерялись».

Это доказательство работы всего стека без железа. Следующий шаг — заменить
`LoRaChannel` на реальный `TransportAdapter` (Meshtastic BLE), когда узлы
будут подключены; интерфейс сообщений уже готов.
