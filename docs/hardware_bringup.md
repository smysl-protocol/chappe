# Первое включение радио (Meshtastic-узлы)

Чек-лист на день, когда приедут ELECROW ThinkNode M1. Всё, что здесь
написано, уже отлажено против мока (`tools/meshtastic_mock/`) — по шагам
и без спешки.

## Что понадобится

- Узел ThinkNode M1 (nRF52840 + SX1262), кабель USB-C.
- iPhone с приложением R+M (сборка с Dev-экраном).
- Мак с приложением **Meshtastic** из App Store на телефоне — только для
  первичной настройки узла (регион, пресет). Дальше оно не нужно.

## Шаг 1. Прошивка и регион (один раз на узел)

1. Подключи узел по USB-C к Маку, включи его.
2. Поставь на телефон официальное приложение Meshtastic, подключись к
   узлу по Bluetooth (узел виден как `Meshtastic_XXXX`).
3. В настройках узла выставь:
   - **Region: SG_923** (тот же регион записан у нас в
     `ios/Chappe/Chappe/Resources/sophie_kb/mesh_config.json` — они должны совпадать);
   - **Modem preset: LongFast** (тоже совпадает с конфигом);
   - Bluetooth-пин запомни/запиши.
4. Убедись, что узел перезагрузился и снова виден по Bluetooth.
5. **Закрой приложение Meshtastic полностью** (смахни из недавних):
   узел держит одно BLE-подключение, открытое приложение займёт его,
   и R+M узла не увидит.

## Шаг 2. Репетиция на моке (можно до приезда железа)

1. На Маке: `swiftc -O tools/meshtastic_mock/main.swift -o /tmp/mesh_mock`
2. Запусти: `/tmp/mesh_mock` (или `--loss 0.2 --delay 500`, чтобы
   посмотреть, как ведёт себя очередь при плохом эфире).
3. В приложении: Dev-экран → Транспорт → **Дальняя связь (радио)**.
4. Строка «Дальняя связь» должна дойти до «радиоканал готов».
5. Отправь сообщение в чате. Мок вернёт подтверждение и эхо — сообщение
   придёт входящим, статус исходящего станет «доставлено».

## Шаг 3. Живой узел

1. Останови мок (Ctrl+C), если он запущен.
2. Включи узел, убедись, что официальное приложение Meshtastic закрыто.
3. В R+M: Dev-экран → секция «Дальняя связь» → поле **«Имя радио»** —
   впиши имя узла (`Meshtastic_XXXX`) и нажми Ввод. Это и есть
   переключение мок → живой узел: одна настройка, без пересборки.
   (Пустое поле = подключаться к первому найденному радио.)
4. Дождись «радиоканал готов».
5. Полный цикл вдвоём: второй узел + второй телефон (или мок на Маке
   рядом) — отправка → «доставлено» → ответ.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| «ищу радио…» не меняется | Узел занят другим приложением (закрой Meshtastic), или имя в поле «Имя радио» не совпадает с настоящим. |
| «радиоканал готов», но ничего не уходит | Смотри строку очереди: «канал занят — жду окно эфира» — это дьюти-цикл, надо подождать. |
| Сообщения уходят, но не приходят | На втором конце другой регион или пресет — шаг 1, пункт 3. |
| Узел просит пин при подключении | Введи пин из шага 1; iOS запомнит его. |

## Что уже учтено в коде

- Наш трафик идёт отдельным портом (PRIVATE_APP=256), а не текстовым
  каналом Meshtastic — чужие приложения наши байты не показывают.
- Наше шифрование конверта остаётся нашим; шифрование канала узла —
  его дело, мы на него не полагаемся.
- Пакеты больше ~200 Б режутся на нумерованные части и собираются
  на приёме; порядок прихода не важен.
- Эфирное время считается: бюджет задан в `mesh_config.json`
  (`airtimeBudgetSecondsPerHour`), при переборе очередь честно ждёт
  и показывает это в статусе.
- Приоритет отправки: SOS раньше всего остального.
