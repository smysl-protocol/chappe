# Погодный пак — формат и контракт (v0, 06.08.2026)

Основание: `docs/reports/weather_layer_estimate_2026-08-06.md`
(решение владельца: вариант Б, старт Б1, формат пака свой с первого
дня; при выходе на краудфандинг — обязательный переезд на Б2).

Два требования владельца, ради которых формат существует (06.08):

1. **Формат проектируется так, будто источник уже наш.** Ни одно поле
   не берётся «как отдаёт Open-Meteo»: имена, единицы, порядок и
   упаковка — наши. Всё, что знает про Open-Meteo (URL, имена их
   параметров, их JSON), живёт в ЕДИНСТВЕННОМ модуле-источнике;
   хранилище, рендер, таймлайн и UI видят только этот формат.
   Переезд Б1 → Б2 меняет модуль-источник и URL — больше ничего.
2. **Свежесть — часть контракта, не украшение.** Пак без времени
   прогона модели НЕ ПРИНИМАЕТСЯ вообще: декодер обязан отвергнуть
   его как битый. Лучше отсутствие погоды, чем прогноз без возраста.
   Возраст считается ТОЛЬКО от времени прогона модели (`run_unix`),
   никогда от времени закачки.

## Формат (JSON, v1)

Один файл = один регион, один прогон модели, все слои и весь таймлайн.

```json
{
  "format": "chappe.weather.pack",
  "version": 1,
  "model": "gfs-0p25",
  "run_unix": 1754625600,
  "fetched_unix": 1754640000,
  "bbox": [7.0, 105.0, 17.0, 115.0],
  "step_deg": 0.25,
  "hours": [0, 3, 6, 9],
  "fields": {
    "wind_u10":    { "unit": "m/s",  "scale": 0.1, "values": [/* int */] },
    "wind_v10":    { "unit": "m/s",  "scale": 0.1, "values": [] },
    "temp_2m":     { "unit": "C",    "scale": 0.1, "values": [] },
    "cloud_total": { "unit": "%",    "scale": 1,   "values": [] },
    "precip":      { "unit": "mm/h", "scale": 0.1, "values": [] }
  }
}
```

- `model` — НАША номенклатура (`gfs-0p25`, `icon-13km`, `blend`), не
  имена параметров чужого API.
- `run_unix` — время прогона модели (issue time), UTC. Обязательное.
- `fetched_unix` — когда данные получены. Обязательное,
  `fetched_unix ≥ run_unix`. В расчёте возраста НЕ участвует —
  нужно для диагностики («данные от вчера, сети не было»).
- `bbox` — [latMin, lonMin, latMax, lonMax], градусы.
- `hours` — смещения сроков от `run_unix` в часах, строго
  возрастающие.
- Сетка: `nLat = round((latMax−latMin)/step)+1`, `nLon` аналогично.
- `values` — квантованные целые, физическое значение = `int × scale`;
  длина ровно `hours.count × nLat × nLon`; порядок —
  срок → широта (с юга) → долгота (с запада).
- Все пять полей v1 обязательны.

## Контракт декодера (реализация — `Weather/WeatherPack.swift`)

Декодер отвергает пак целиком (честной ошибкой, без частичного
приёма), если: неизвестный `format`/`version`; нет `run_unix` или он
абсурден (раньше 2020, больше часа в будущем); `fetched < run`;
кривой `bbox` или шаг; `hours` пусты/не возрастают; длина любого
поля не сходится с сеткой; отсутствует обязательное поле.

Замок: `WeatherPackTests` — «пак без времени прогона отклоняется»,
«возраст считается от прогона, не от закачки» (ожидания посчитаны
руками). Слом проверяется удалением проверки из декодера.

## Что обязан показать UI (из решений владельца)

- Возраст прогона у любого видимого слоя: «прогноз от N ч назад»;
  старые данные — прямым текстом («прогноз от вчера, сети не было»).
- Дисклеймер разрешения при включении слоёв: сетка 13–27 км —
  **«прогноз общей картины, не локальных явлений»** (формулировка
  владельца, 06.08). Локальный шквал такая сетка не видит.
- Атрибуция источника данных (CC BY 4.0: Open-Meteo / DWD / NOAA —
  по фактическому источнику пака).
- Слои по умолчанию выключены; состояние кнопок персистится.

## Словарь

В интерфейсе «пак» не употребляется (словарь): для человека это
«прогноз» или «погодные данные». Термин «пак» — только в коде,
спеках и отчётах.
