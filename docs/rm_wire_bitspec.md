# Побитовая спека провода Smysl-кодека (v1.3.0) — 03.08.2026

Статус: **нормативный документ формата.** До 03.08 побитовой спеки не
существовало — формат жил только в коде, и якорь корректности был
замкнут сам на себя (см. `docs/reports/codec_tests_audit_2026-08-03.md`).
Этот документ написан по решению владельца (часть II, п.3) и является
источником истины для `tests/rm_hand_vectors.json` — векторов,
посчитанных вручную по этому тексту и НЕперегенерируемых.

## 1. Wire-блоб семантической нагрузки

```
[отпечаток таблицы 4 Б, big-endian][varint: число юнитов][битстрим][паддинг нулями до байта]
```

- **Отпечаток** (v1.3.0 = `0x883E14BE`): FNV-1a 32 бита
  (init `0x811C9DC5`, множитель `0x01000193`), вход — байты строки
  `v{версия};`, затем для каждой записи словаря `{code}:{bits};`
  **в каноническом порядке (bits, code)**, затем строка `litchars;`
  и для каждого символа litchars `{cp}:{bits};` **по возрастанию cp**
  (litchars в отпечатке с 03.08 — решение владельца: при совпадающем
  словаре и разных litchars литералы декодировались молча неверно;
  прежний отпечаток без litchars был `0x11AE146D`).
- **Varint** — LEB128: 7 бит на байт, младшая группа первой, старший
  бит байта = «есть продолжение». Примеры: 1 → `01`; 128 → `80 01`;
  300 → `AC 02`.
- **Битстрим** — MSB-первый: биты пишутся от старшего к младшему,
  байты заполняются слева направо. Финальный неполный байт добивается
  нулями справа.

## 2. Канонический Хаффман словаря

Из словаря берётся ТОЛЬКО поле `bits` каждой записи. Порядок
назначения: сортировка записей по `(bits, code)`. Значения кодов:

```
canon = 0; prev = 0
для каждой записи в порядке:
    canon <<= (bits - prev);  prev = bits
    код записи = canon (ширина bits)
    canon += 1
```

Следствия (v1.3.0): первый канонический код — `you` (4 бита, 0000);
последний — `hazard_electric` (16 бит, 0xFFFF — все единицы).
Декодер наращивает код по биту; длина > 24 бит = битый поток.

## 3. Escape-пути

Все escape — обычные записи словаря, кодируются своим Хаффман-кодом,
после которого идёт нагрузка. **«Выравнивание»** = добить текущий байт
нулями до границы; после байтовой нагрузки битстрим продолжается с
нового байта БЕЗ обратного выравнивания.

| Escape | Нагрузка |
|---|---|
| `esc_number` | выравнивание, varint значения |
| `esc_time` | выравнивание, varint минут суток (0–1439) |
| `esc_amount` | выравнивание, 1 Б индекс валюты (таблица CURRENCIES, алфавитная, заморожена; 255 = «валюта литералом»: следом ровно 3 Б ASCII), varint суммы |
| `esc_local` | выравнивание, 1 Б тега: `0x80` → следом 1 Б индекса эмодзи (таблица emoji_v11, 255 записей); иначе тег = id фразы |
| `esc_literal`, `esc_name` | выравнивание, 1 Б длины (число **скаляров Unicode**, не байт; максимум 255, больше — честный отказ кодека), затем битстрим символов вторым Хаффманом (litchars, §4) |
| `esc_extension` | **БЕЗ выравнивания**: сразу 12 бит индекса (0–4095, big-endian в битстриме) |

## 4. Символьный Хаффман литералов (litchars v1.2)

- Таблица: `litchars_v12.json` — 86 записей (cp, freq) + escape cp=0.
- **Длины кодов** выводятся из freq классическим Хаффманом с кучей;
  тай-брейк детерминирован: элемент кучи — `(freq, порядковый номер
  вставки, ключи)`, объединённые узлы получают следующий номер после
  исходных 86. Одинаково в python и Swift (паритет проверен hex-в-hex).
- Канонические коды: сортировка по `(bits, cp)`, назначение как в §2.
- Символ вне таблицы: код cp=0, затем **21 бит** скаляра Unicode
  (максимум U+10FFFF — 21 бит впритык, см. аудит пределов).
- Отпечаток litchars `0xC3`: FNV-1a 32 по строкам `{cp}:{bits};`
  **в порядке ВОЗРАСТАНИЯ cp** (не в каноническом!), младший байт.
  ⚠️ Формулировка в FREEZE.md («по cp:bits; канонических длин»)
  неоднозначна — нормативен порядок возрастания cp, как здесь.

## 5. Находки при написании (неоднозначности, зафиксировано)

1. **Побитовой спеки не существовало** — главная находка. Этот
   документ закрывает дыру; вектора `rm_hand_vectors.json` делают
   его проверяемым.
2. **Порядок строк отпечатка litchars** (§4) — в FREEZE.md
   неоднозначен; при выводе «по канону» получается другой байт
   (0x2D). Нормативен порядок cp.
3. **esc_local `0x80`**: спека v1.1 (`dict_freeze_v1_1.md`) обещала
   id `0x80–0xFF` локальному словарю пары, но `0x80` занят
   маркером эмодзи. Фактическая разметка: `0x00–0x7F` фразы,
   `0x80` + байт — эмодзи, `0x81–0xFF` декодируются как фразы
   (локальный словарь пары фактически не реализован).
4. **Длина литерала — в скалярах Unicode**, не в байтах UTF-8 и не в
   графемах (эмодзи из нескольких скаляров занимает несколько единиц
   длины). Нигде не было записано.
5. **Резерв под каскад расширения** (решение владельца 03.08, п.6
   части III): индекс `esc_extension` **4095 (0xFFF) зарезервирован**
   под будущий 16-битный индекс второго уровня и не должен
   назначаться словам. Провод не меняется, пока резерв не активирован.

## 6. Правило неперегенерации

`tests/rm_hand_vectors.json` посчитан вручную по этому документу
(вывод каждого вектора — в поле `derivation`). Перегенерация
кодеком ЗАПРЕЩЕНА и технически заблокирована corpus_guard'ом:
расхождение кодека с векторами = дефект кодека или осознанная смена
формата (новая мажорная версия + новый документ), но никогда —
повод «обновить вектор».
